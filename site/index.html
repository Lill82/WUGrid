Watch every server through a Windows Update restart round

WUGrid shows each server's state every few seconds, restarts the ones you pick without forcing them, and checks what a green restart can hide. It works agentless over WMI/DCOM, so it runs where WinRM is closed and installs nothing on the servers.

Get started View on GitHub

The demo round, 26 minutes in. Simulated servers; nothing is contacted.

Agentless

ICMP and WMI over DCOM, with one reused connection per server. It uses only what every Windows Server has: no WinRM, no agent and no ConfigMgr.

Observe by default

Watching and verifying never change a server. A restart is a named action: you see the plan, confirm it, each server is checked again, and the result is recorded.

Rules from a real round

Built on a 54-server round. Chained reboots, a minute of “access denied” while a server boots, and component cleanup are routine and shown as such. Real failures are flagged.

Watch

Every server, at a glance

Each server gets its own worker that pings it and reads its last boot, servicing processes and the CBS and Windows Update reboot keys. A cut-off time decides what counts as restarted.

RESTART PENDING
not restarted yet; CBS packages or Windows Update waiting
NO RESTART PENDING
not restarted yet; nothing pending
INSTALLING
servicing before the shutdown
DOWN
no ping, with how long it has been down
BOOTING
answers ping, WMI not ready yet
BACK
restarted after the cut-off, checks clean
BACK · PENDING
restarted, but a restart is pending again
BACK
restarted, but an update failed or a service is not running

There are alarms for a server down 15 minutes or still pending 20 minutes after its boot, and one line when every server is back clean with its checks done.

Verify

Catches the restarts that only look green

When several months of cumulative updates were staged on top of each other, only the oldest committed. The servers came back looking clean, but at an old patch level. Once a server is back, WUGrid reads its System log and services (read-only) and flags:

  • an update that failed (Windows Update event 20), with the error explained;
  • a service not running that ran before the restart, who changed its start type, and why it did not start — timed out at start, a service it depends on, its account — and whether it failed at the boots before too; a stop you know about (a role being removed) can be marked expected: shown with the reason, not flagged;
  • who restarted it and why (event 1074), each boot and the build it came up on.

Double-click a row for the details. The Build column shows the build before and after.

Restart

Restarts that never force

  • Only servers with no update work running can be ticked, and each is checked again just before the restart is sent.
  • Never forced (Win32ShutdownTracker, reboot without force): running programs can delay or cancel it.
  • A server with a user signed in is skipped, naming who: Windows refuses a restart that is not forced while anyone is signed in.
  • An optional warning period, during which shutdown /a on the server aborts it.
  • Check only runs everything but the restart call.
  • Each request and result goes to an append-only audit log, and your comment shows up in event 1074 on the server.
Report

The round, on one page

Report… saves the round as a self-contained HTML page, with a summary and a “needs attention” section to mail or attach to a change. It can also save CSV for Excel. wugrid-cli verify makes the same report from the command line.

Explain

Every error code, explained

The catalog has 438 CBS, Windows Update, WMI and Win32 codes, with descriptions and fixes from Microsoft Learn and WUGrid's own notes for the codes it runs into on real rounds. Search by code or by word. Hover a note in the grid for a summary.

Decisions use event IDs and error codes, never message text, so they work whatever language the servers use.

Console

The same round in a console

wugrid-cli watch uses the same probe, states, alarms and checks as the window. Its grid redraws every second; when the servers don't all fit, clean ones fold into a single line. It re-reads the server list file when it changes.

Run it headless and it prints one line per change and alarm, then stops once every server is back clean. A script or a background task can follow that output.

Commands

> wugrid-cli watch --list servers.txt --since 2026-10-17T15:00
> wugrid-cli watch --list servers.txt --headless \
      --state state.json --events events.jsonl
> wugrid-cli verify SRV01 SRV02 --html round.html
> wugrid-cli check SRV01         # DNS, ping, WMI, admin$
> wugrid-cli error 0x800F0840   # explain a code

--state rewrites the round as JSON on every refresh and --events appends one JSON line per event. The exit code says whether every server ended back clean.

Get started

WUGrid is in early development. There are no release downloads yet, so build it from source; it takes a minute.

Try the demo

A simulated 75-minute round of 14 made-up servers, with every pattern from the field notes. No server is contacted.

> WUGrid.exe --demo
> wugrid-cli watch --demo

Build

Needs the .NET SDK 8 or later. The .NET Framework 4.8 reference assemblies come from NuGet.

> git clone https://github.com/Lill82/WUGrid
> dotnet build WUGrid.sln -c Release
> dotnet test WUGrid.sln

Requirements

  • Windows with .NET Framework 4.8 on the admin workstation
  • ICMP and DCOM/RPC to the servers (SMB for the admin$ check)
  • An account that is an administrator on them
  • Nothing installed on the servers; WinRM not needed

Where it is going

From watching a round to driving it: scan, install, restart in waves, verify.

  1. M0doneFoundation: solution, tests, CI, anonymised field notes
  2. M1builtWatch: live grid, console grid, headless events, state JSON
  3. M2doneVerify: update results, services baseline, who restarted, report
  4. M3first cutRestart: guards, re-check, never forced, audit, expected stops; waves and a protect list next
  5. M4nextUpdates: scan → approve → install → restart → verify, agentless
  6. M5plannedRelease: docs, release zip, versioning
